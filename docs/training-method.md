# 训练方法与 Agent 接手

> 难度证据更新：后续发现 DIP 读回不能证明游戏内部已切换难度。
> 本文的历史跨难度结论需重新验证，参见 [0.1.1 修复说明](difficulty-fix.md)。

这份文档提炼自项目开发期间的本机 Skill 和专项复盘，供其他玩家与 Agent
理解、复用训练思路。它不依赖原开发者的目录、实时交接文件或历史存档。
演进过程见[训练历史](training-history.md)，具体例子见[对手经验](matchup-lessons.md)。

这里的“训练”是分析失败、修改固定 Lua 策略并做对照实验，不是训练神经网络。
Python 编排比赛和记录证据，Lua 读取当前游戏状态并按游戏帧发送普通按键；
AI 参与离线分析和代码改进，运行时不需要模型。RAM 与执行结构见[实现说明](architecture.md)。

## 下载项目后能直接做什么

当前发行版提供冻结 V4 的安装、游玩验证、审计和报告；**没有移植旧版的
存档采集器、批量训练 runner 或候选生成器，也没有 `astra-sf2 train` 命令**。
这份方法说明不能当作那些工具已经随项目提供的承诺。

先按 [AGENTS.md](../AGENTS.md) 补齐环境，以同一 CLI 复验基线：

```sh
astra-sf2 doctor
astra-sf2 verify --difficulty 3
```

需要跨难度固定次数测试时，用 `--difficulty all --attempts 5`；需要检验五连时，
用 `--difficulty all --attempts 20 --consecutive 5`。默认正常速度，明确选择
`--speed fast` 才快进。每次记录运行命令、环境、策略身份、实际尝试数和失败。
运行后使用 CLI 打印的目录执行 `audit`、`report`；图片复核另按[验证规则](verification.md)执行。

只有在用户要求优化时才开展新训练。另建实验分支，例如 `codex/train-vega`，
独立保存候选和输出；保留 V4 原文件及其来源哈希。当前 CLI 的身份校验针对
冻结 V4，不能直接替换文件就声称候选已获支持或通过验证；新策略需要明确的
版本身份、适配与检查。以下流程用于设计新的训练工具和实验。

## 一次改进的完整流程

1. **先验证基线，找真实弱点。** 从自然结束、重新投币的路线中统计每个对手的
   小局与整场失败。优先解决反复导致整次挑战结束的对手，同时观察小局退步。
   先区分真正输掉比赛、结算漏判和控制异常；三者的解决方向不同。
2. **采集有代表性的开局。** 训练时在目标对手满血、99 秒、0:0 的完整 R1
   开局保存状态，检查角色和动作已经初始化。记录游戏版本、原生难度、对手
   出场位置、前序路线、存档哈希和速度。尚未到目标就失败的采样也要保留。
3. **提出可检验的单项假设。** 例如“这次受击源于过早对空”，先只修改该触发
   条件，保留其他输入、恢复阶段和防守。不要一次同时改距离、拳脚强度和时序。
4. **同条件配对。** 基线与候选使用同一开局、难度、速度和起手等待。历史工具
   每场恢复一次后固定中性刷新 2 帧，再执行预声明的额外等待（lead）。把这些
   帧数记入条件，不能把不同起点的结果当作同态对照。
5. **解释首次分岔。** 对齐两条轨迹，找到第一次选招不同的位置，检查当时状态、
   已发输入及随后受击。某次防守改变了后续节奏而赢下整场，不等于它直接挡住
   了目标攻击；后续小局也已经不是原轨迹。
6. **扩大回归，使用预留开局。** 同时覆盖旧成功开局、真实败局、新路线、不同
   出场位置及目标难度。预留条件一旦用于调参，就转为开发样本。记录新增败局，
   不以开发样本全胜代替推广证据。
7. **冻结后重新正式验证。** 固定选招表、策略、Core、环境与停止条件；从自然
   投币开始验证完整路线，全部失败留在分母。进入训练或更换版本后，新开一组
   验证，不能接续旧版本的连胜。训练存档的胜段不能拼接为正式通关。

## 怎样减少训练耗时

早期时间浪费在 Agent 每小段操作后等待、反复截图与读状态、逐局人工调度，
以及为了训练尾关而反复打完整路线。后来把整场决策放进 Lua、整批调度放进
Python，批次结束再集中分析，减少了模型与模拟器之间的往返。

| 消耗来源 | 后续训练工具应采用的办法 |
|---|---|
| 为每个候选重打前面十人 | 训练专用 R1 存档复用；正式验证仍走完整路线 |
| Agent 逐招、逐局等待 | 预先固定整批计划，由 Lua/Python 连续执行 |
| 全角色、全批次都保存大量诊断 | 训练筛选先记轻量结果，代表性失败再采完整轨迹 |
| 从掉血截图猜起因 | 保存选招原因及受击前上下文；Vega/Sagat 曾扩到 120 帧 |
| 对已淘汰候选不断重复 | 预声明预算与淘汰条件，失败后按规则停止 |
| 把重复路线当成新样本 | 比较存档哈希、前序路线及完整开局/结算轨迹 |

当前正式 CLI 的完整轨迹是审计材料，不应为了提速删除；轻量采集建议针对
未来独立训练工具。快进减少墙钟时间，但招式和等待仍按模拟游戏帧执行。
比较效率时固定样本数量、采集级别、环境和策略，并分别测量采样、加载刷新、
对局执行、写盘及分析时间；不能把减少样本或漏记失败造成的变快归功于执行器。

同一模拟器只允许一个控制器。使用多个 Agent 时，可以分配已结束日志的分析、
候选代码审查和离线测试；其他 Agent 不向活动实例发送观察、截图或输入命令。
不确定的控制命令超时后先核实实际状态，不自动重发。

## 统计与判断

| 指标 | 口径 |
|---|---|
| 小局胜率 | 胜 /（胜 + 负 + 平）；按实际 rounds 计数，2:1 的比赛可能另有平局 |
| 对手整场胜率 | 有效整场胜 / 有效已完成整场数 |
| 正式通关率 | 通关数 / 本组实际尝试数；异常尝试单列并保留在正式尝试分母 |
| 连胜 | 同一冻结版本、同一难度下连续通关；失败或 invalid 中断 |
| 待定记录 | 无效比赛中已结算的小局单列，未结算局不猜胜负 |

训练、采样和正式验证分别统计；探索中的失败与选中候选的复测成绩分别列出。
至少报告每个对手的小局 W/L/D、整场胜负、异常数、样本条件和版本。
所有原始证据保存在本地实验目录，不提交 ROM、存档、逐帧日志或历史台账。

重复同一个存档、不同 lead 或不同文件名不保证独立样本。自然投币能够观察到
不同路线，但也不能直接视为独立随机试验。五连是观察到的连续结果，不是
真实胜率 100% 的证明；必须同时报告累计通关率与当前/最长连胜。

## 新实验记录模板

以下是文档模板，不是现有 CLI 的计划文件格式：

```text
问题：哪位对手、哪类真实失败，还是控制/判胜异常？
基线：策略/选招表/Core 哈希，MAME/ROM 版本，原生难度
假设：一个可观察的原因；一项候选改动
条件：R1 来源与哈希、出场位置、速度、刷新帧、lead
划分：开发条件、预留条件、重复轨迹如何识别
预算：候选数、最大场数/时间、淘汰与停止条件
结果：小局 W/L/D、整场胜负、invalid、所有回归
解释：首次分岔、直接观察、尚未证明的因果
决定：采用/淘汰/证据不足；新版本身份与正式验证计划
```
