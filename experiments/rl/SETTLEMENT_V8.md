# 双 KO 后的最后一次计时递减

一次训练在 Blanka 第三小局的双 KO 后触发结算保护，父进程随后收到 `EOFError`。首个异常来自原生结算未识别，不能把随后出现的管道错误归因为 GPU 或 OOM。异常批次保留为 invalid；已完成的模型检查点与整个训练批次是否完成是两回事。

实际记录中，第 5255 帧双方生命及显示生命分别为 22、21，计时 36；第 5256 帧双方同时进入 KO，计时仍为 36；第 5257 帧计时最后减为 35，随后冻结。比分始终 1:1。第 5616 帧画面明确显示 DOUBLE K.O.，第 5900 帧显示 ROUND4、双方满血。旧 v7 要求从第一帧 KO 起计时完全不变，因此取消了这个平局候选。

v8 仅给这一边沿增加严格例外：

- 必须观察到紧邻原生前帧双方正生命、显示生命一致、旧比分及零 TIME 锁存，然后双方同时 KO。
- 仅允许 KO 后紧接的一帧将正计时减 1，且不能减至零；双方仍 KO、TIME 锁存仍为零。之后计时必须保持不变，第二次变动不接受。
- 保留已有双 KO 的显示血量单调耗尽、至少 360 帧成熟、双方落地及有效终止姿态要求。
- 只有原生进入同比分的完整下一小局开局才确认 draw。未授分本身不是平局证据，也不由此推断 win/loss。

原始 `stop.timer=36`、`settled.timer=35` 及确认开局分别保存，不改写游戏 RAM、原始状态或历史结果。TIME、普通 KO、晚 KO 和已有 invalid 路径不变。神经网络 4516 维输入、128×128 架构、85 个动作、奖励与已经修复的输入时序保持原样。

## 构建

```sh
python -m experiments.rl.perception128_draw_builder \
  --output .local/rl-code/perception128-draw-v8
```

可以用 `--source` 指定已冻结的 timing 父包；省略时从公共源码构建完整父级，不依赖私有历史文件。新包名为 `astra_sf2_rl_perception128_draw`，schema 为 `astra.rl-screen-perception128-settlement.v8`，结算协议为 `native-pip-ko-late-ko-time-and-confirmed-draw-v8`。父包和所有派生执行文件均保留哈希审计，兼容旧模型的完整参数与优化器；旧执行包不被修改。

## 验证范围

六项结算测试覆盖此边沿正例、错误计时变化、缺失或不相邻前帧、已 KO 的前帧、比分改变、过早新局及旧 v7 和更早回归。另有独立构建测试检查派生文件集合、未变执行字节、128 模型、篡改拒绝与搬迁后校验。

一次单 MAME 原生重放执行原 308 个宏并继续至第 5947 帧。原诊断保留的 2589 帧状态和 163 个有完整历史的 4516 维观测精确一致；所有 5947 帧的原生时差通过。第 5847 帧确认 draw，旧局成熟状态仍取第 5835 帧；R4 首个宏的第 5936–5947 帧完整执行，历史重置和实际端口均通过。两张双 KO / ROUND4 截图已实际查看。

探针原先额外要求四个 R4 决策，但帧预算仅覆盖第一个，因此其原始 scope 断言失败记录保留。独立审查只认可上述已录制范围，没有补跑或改写原结果。这是结算修复的原生证据，不是正式通关，也不证明训练胜率。
