# 非 TIME KO 的通用原生结算

计时先归零、投技随后完成 KO 的独立补充见 [v7](SETTLEMENT_V7.md)；本页 v6 源和验证记录保持不变。

128×128 首次长训练因一场 Guile 被 Ken 踢投击倒后的结算异常停止。游戏已经给 Ken 加一小局，败者最终保持动作字节 `a2`；原结果识别只对少数角色的这种状态作例外处理，因此漏判并在下一小局到来时正确报 invalid。这个运行保留为控制异常，不能计为输局或完成训练。

v6 为非 TIME KO 增加通用证据分支，不再依据败者动作字节或具体动画地址白名单。它要求：

- 终止快照中恰有一方生命为 KO 哨兵 `-1`，另一方生命为合法存活值；角色及非零计时保持一致。
- 连续原生帧中败者仍为 `-1`，显示血量单调降至 `-1`；赢家生命和显示血量保持一致。
- 原生比分只向对应赢家增加一小局，并连续稳定至少 360 帧，同时满足原先自终止起至少 360 帧的成熟期。
- 双方最终落地，赢家处于原胜利状态，败者显示血量耗尽；不能用空缺比分或下一局的满血推断赢家。

旧 Core 和 v5 规则先运行，已有结果与 invalid 不会被覆盖。新证据一旦不一致，该分支在当前小局内永久取消；旧规则若也无法证明结果，仍以原 unresolved/新局提前到来规则报 invalid。TIME、双 KO、平局与旧可识别 KO 保留原协议。没有修改游戏 RAM、动作、模型、奖励公式或优化器。

原始问题轨迹的离线重放：第 1468 帧出现 KO，第 1469 帧原生比分变为 1:0，第 1829 帧完成稳定 360 帧的证明并记录 Ken 小局胜利。随后原游戏第 2089 帧的下一局完整开局仍为 1:0。

独立原生重放已通过，耗时 41.24 秒：batch 与连续原生路径的 139 次决策观测、状态和实际输入端口一致；第 1829 帧均确认 1:0，并继续完成第二小局的 17 次决策。第 1830 帧截图经过实际查看，显示 Ken 获胜、Guile 倒地。这证明本例的结算与跨小局接续已修复，不代表策略通关能力或所有未知结果都已覆盖。

## 独立构建

```sh
python -m experiments.rl.perception128_settlement_builder \
  --output .local/rl-code/perception128-ko-v6-001
```

也可用 `--source` 指定已冻结的 perception128 源包。生成器保存完整旧父源及 SHA256，严格检查只有结果适配器和源身份接线变化，模型架构、神经输入和动作接口保持原身份；已经完整保存的兼容 128 模型可以加载，未完成运行不自动恢复或冒充成功。运行入口仍为 `initialize`、`batch_train`、`export`、`native_continuous`。

离线测试覆盖双向小局/整场胜利、成熟前不得结算、缺少比分、比分/血量/计时或帧连续性反例、落地和赢家胜利状态、旧 KO 原时序、round reset 清理以及 v5 的 TIME/双 KO/平局回归。另验证公共构建、搬迁、源篡改拒绝及模型接口不变。原生重放、后续训练与正式投币结果分别保留。
