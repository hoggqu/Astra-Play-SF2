# 冻结版本的连续训练与验证

`versioned_campaign.py` 是只依赖 Python 标准库的独立编排器，可以单独复制到另一台机器。模型结构、训练和验证全部由明确指定的冻结代码包提供；编排器不实现打法，也不修改模型宽度。

```sh
python versioned_campaign.py \
  --python /path/to/rl-venv/bin/python \
  --code /path/to/frozen-code \
  --package astra_sf2_rl_managed \
  --dataset /path/to/train-manifest.json \
  --config /path/to/astra-config.json \
  --output /path/to/new-campaign \
  --cycles 20 --steps 409600 --workers 16 --block 128 --checkpoint-every 4096 --attempts 3
```

Windows 使用对应的 Python 路径，参数意义相同。子进程通过 `ASTRA_SF2_CONFIG` 使用指定配置，`PYTHONPATH` 只加入冻结代码根目录及其 `src/`，不依赖远程仓库的新旧状态。

`--block` 指定每次批量请求的决策数，支持 1、16、32、64、128、256，默认 128；它改变 IPC 批量大小，不改变每个动作的 12 帧时长或 PPO 的 256 步采样周期。`--steps 409600` 是每轮训练结束后进行自然投币验证的外部间隔，不是 PPO 内部样本批量。4、8、16 worker 每次 PPO 更新分别采集 1024、2048、4096 次决策；因此同样 409600 次决策分别包含 400、200、100 次 PPO 更新。

可选 `--first-cycle-steps` 仅替换本次编排的首轮训练预算，之后每轮恢复 `--steps`；不传时行为不变。它同样必须是 `workers×256` 的正整数倍，实际首轮预算、每轮请求与完成步数均记录并核对。例如已有完整检查点与一次短测合计新增 294912 次决策，下一次启动可设 `--workers 8 --steps 409600 --first-cycle-steps 114688`，补足 409600 后首次验证；该参数不会自动推断此前步数，也不会合并或隐藏先前记录。

`--checkpoint-every` 默认 20480，必须是 `workers×256` 的正整数倍。设为 4096 时，16 worker 每次完整 PPO 更新都保存可恢复的完整 ZIP；它包含 Adam，异常时可从最后完成的检查点另开目录续跑。检查点间隔及子进程实际间隔会核对并记录，不会自动重试异常对局。

当前 managed 执行器支持 `--workers N` 的任意正整数。直接使用此底层命令时，步数和保存间隔仍需满足上述整批约束；面向用户的 `autotrain` 入口会自动向上对齐。可以在本机另开 4 worker 的独立候选，与远程候选使用不同输出目录和各自的 MAME 进程；两者都可设置 `--steps 409600`，并各自自动投币验证。可从同一个完整 ZIP 起步，但随后各自保留自己的模型、Adam 与失败记录，不合并跨机器梯度或混算两者通关率。4 worker 每个采样周期的数据量较小，同样决策数会做更多次 PPO 更新，因此并非与 16 worker 完全等价的训练轨迹；先测本机吞吐再决定是否长跑。

首次创建完整 PPO ZIP，之后每轮训练都加载上一轮最后完成的 ZIP 和 Adam 状态。每轮训练结束，用该模型在 Normal 难度自然投币最多三次，默认首次通过十一场原生完整对战即停止。`--no-stop-on-clear` 会继续后续训练轮直到预算结束；各轮模型与结果仍分别保存，不合并成固定策略的胜率。验证失败继续训练当前最新模型，不回退到某个历史评估最优模型。验证中不读档、不继续、不重置，不使用 V4；训练仍可按冻结训练协议加载训练状态。只读取训练数据集，不选择开发集或保留集模型。

`result.json` 和每轮 `cycle.json` 保存源文件、配置、数据集和模型哈希、阶段命令、退出码、完整尝试结果及累计对手成绩。`evaluation_matchups` 按对手 ID 累计单局胜/负/平，以及整场胜/负；来源是已审计的原生对战文件，训练采样不混入这张表。阶段完整日志和每次失败均保留。

训练阶段必须退出 0。验证退出 1 仅在全部指定尝试均为有效失败时继续；退出 2、缺失审计、模型或源文件变化、Adam 状态丢失，都会立即停止并记录 invalid。成功必须同时有原生时序审计、动作/观察接口审计及逐次尝试审计。程序退出码：0 首次达标，1 预算结束未达标，2 异常。

不复用既有输出目录，不重放中断的验证。需要续跑时，另建输出目录，并用 `--init-model` 指向原结果 `latest_model` 所记载的完整 ZIP；保留之前的失败目录。这样延续当前已完成模型和优化器，也不会掩盖中断记录。运行中的源码或配置不得替换。

二十六项无需 MAME/Torch 的测试覆盖有效失败后继续、首次通关停止、最新 Adam 传递、异常退出停止、缺失审计拒绝、源文件变化、已有目录保护、完整 ZIP 要求与累计成绩，以及 4 worker 转发、整数限定和各 worker 数对应的完整更新/检查点倍数、首轮预算覆盖及错误完成步数拒绝。

## 时长预算与安全停止

`--cycles` 表示训练与验证循环次数，一轮可以包含很多次 PPO 参数更新；它不是街霸小局数。也可以只给 `--max-duration 3600`，或同时设置两种上限。原有只给 cycles 的调用保持不变。

时长是软预算。支持 `ppo-update-stop-file-v1` 的新训练包通过 `ASTRA_RL_STOP_FILE` 接收停止请求，在本次完整 PPO 更新结束后保存包含 Adam 的最终 ZIP。编排器核对实际步数、完整更新标记、模型与源码身份后记录 `budget_stopped`，不把正常到时算成 invalid。旧包没有该协议时，只能等完整训练阶段结束；不能承诺在下一次更新处停止。

加 `--evaluate-on-stop` 可在时长到后对最终模型再运行一次正常自然投币评估，提供最新模型的成绩；收尾更新和最终评估可能使总时长超过指定值。默认不开启此选项。时间到时若已在自然投币验证中，会让当前验证子任务正常完成，保留所有已审计尝试，不暂停对局、不把取消算输局。

Ctrl+C 请求安全停止：训练保存完整更新后退出；尚未开始的评估不会新增，即使设置了 `--evaluate-on-stop`。如果已在验证中，则等待当前验证子任务结束。结果记录 `cancelled`，CLI 退出 130。关闭终端、强制结束进程或系统断电不属于这个协议；这种情况下只能使用此前已完整落盘的检查点。`--timeout` 仍是独立的子进程故障保护上限，不是正常时长预算。

结果新增 `max_duration_seconds`、`stop_reason`、`any_clear`；每轮分别记录 `training_steps_requested` 和实际 `training_steps`。到时安全停止退出 0；保留旧调用的兼容性，轮数用尽但未通关仍退出 1，异常退出 2。上层面向用户的训练入口可把正常轮数结束解释为任务正常完成。
