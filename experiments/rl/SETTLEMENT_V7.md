# 计时归零后完成的 KO

第二次长训练发现另一种真实结果：计时首先归零，但已经开始的投技继续完成，游戏随后按 KO 给 Ken 加分。异常记录保留，既不算训练完成，也不算失败小局。

问题轨迹中，第 3052 帧计时为零，Ken 生命 10、Dhalsim 生命 15；第 3058 帧 Dhalsim 才进入 KO，第 3059 帧原生比分变为 Ken 1:0。双方 TIME 血量锁存始终为零，败者显示血量随后从 15 降至 -1。这不能按最初的 `10 < 15` 判 TIME 负，也不能仅凭计时归零就排除伤害 KO。[v6](SETTLEMENT_V6.md)只接纳终止时已经发生的非 TIME KO，因此未识别这个结果。

v7 保留 v6 全部旧规则，仅补充一条经过观察确认的边沿：

- 紧邻的上一原生帧已经计时为零，双方生命均为合法正值、显示血量相符、比分未增加，且双方 TIME 锁存都为零。
- 当前帧恰有一方变为 KO 哨兵 `-1`，存活者生命不变，双方锁存仍为零，没有已建立的 TIME 判定；缺失前帧或已经 KO 的前帧不能补造这个证据。
- 此后沿用 v6 的连续证据：唯一对应原生胜局增量稳定至少 360 帧、败者生命保持 KO 且显示单调降至 -1、赢家生命及显示一致、双方落地、赢家处于胜利状态。新边沿路径另要求 TIME 锁存始终保持零。

这不预测未来结果，不以剩余血量比较代替原生比分，也不把未授分视为平局。已有 Core/TIME/双 KO/平局结果与 invalid 仍优先；新证据破坏后永久取消当前小局的这个补充分支。

原始终止轨迹的离线重放在第 3419 帧确认 Ken 1:0，即原生授分后连续 360 帧。回归覆盖双向及同帧授分、缺失/非相邻前帧、之前已授分/已KO/锁存、后续错误比分/锁存、提前新局，以及完整 v6 和更早 v5 契约。源构建另检查只有结算及身份接线变化，兼容 128 模型可以加载；神经观测、85 动作、奖励、优化器和原生输入时序未修改。离线证明仍需独立原生重放确认。

## 独立构建

```sh
python -m experiments.rl.perception128_late_ko_builder \
  --output .local/rl-code/perception128-ko-v7-001
```

可用 `--source` 指定已冻结的 v6 源包。无该参数时从公共源码完整构建；生成包包含所有父级来源及哈希，支持搬迁。旧 v6 执行包与历史结果不被改写，CLI 的训练、导出和自然投币入口保持不变。
