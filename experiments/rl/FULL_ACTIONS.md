# Ken World Warrior 的完整招式输入接口

实验接口 `ken_actions85_full_v1`：85 个离散输入选项，每次仍执行 12 个原生游戏帧。
范围是本项目使用的 **Ken / Street Fighter II: The World Warrior / World 910522**，
不是替其他角色提供所有招式，也不包含后续版本才有的招式。
这次补全输入能力，不修改冻结 16 动作模型，不表示新模型已经训练或通关。

## 覆盖范围

| 输入 | 如何提供 |
| --- | --- |
| 站立／近身／远身的轻中重拳、轻中重脚 | 六个单键；由游戏根据位置决定近身或远身版本 |
| 蹲下的六种普通攻击 | 下、下前、下后各自可配六个攻击键 |
| 空中的六种普通攻击 | 起跳后可选任意攻击键；垂直跳与方向跳的实际版本由游戏决定 |
| 八方向与回中 | 九种方向均可单独选择，也可配六个攻击键 |
| 三档波动拳 | 下 → 下前 → 前＋轻／中／重拳 |
| 三档升龙拳 | 前 → 下 → 下前＋轻／中／重拳 |
| 三档旋风腿 | 下 → 下后 → 后＋轻／中／重脚 |
| 投技输入 | 前／后＋中拳、重拳、中脚、重脚均可请求；距离与时机由游戏判定 |

Capcom 的 World Warrior 官方说明书介绍了 Ken 的 Shoulder Throw、Back Roll，
以及以上三种特殊技的方向输入和任意拳／脚键。
它是家用版说明书，不能单独作为本项目街机 ROM 的帧数、投技范围或
每种输入实际发动成功的证明；街机输入与动画必须另做原生检查。
[Capcom 官方原版说明书，第 6–9、24–25 页](https://captown.capcom.com/uploads/game/manual/23/SF2_en_G.be3a67c7-ad2f-47f6-9619-6ae47a163188.pdf)

本次另外直接核对了本地街机 ROM（程序镜像 CRC32 `43fcc23e`）：Ken 的普通攻击
入口表项 `0x2CE70` 指向 `0x324F0`；按钮分类器 `0x2DFC` 区分拳／脚与轻／中／重；
投技检查 `0x32562` 要求横向输入并排除轻攻击档，`0x325C8` 根据拳／脚组选取投技。
因此，前／后＋中拳、重拳、中脚、重脚有实际 ROM 依据，非根据后续版本猜测。
成功投出仍受原生距离和对手状态检查影响。

不把后续版本 Ken 的 Knee Bash 或空中旋风腿当作本版本已验证的独立招式。
模型仍可在空中尝试旋风腿输入，执行器不会因它无效而拦截。

## 稳定编号与机器可读描述

| ID | 内容 |
| --- | --- |
| 0–15 | 保留 `ken_actions16_pulsed_normals_v2` 的动作编号和逐帧按键波形 |
| 16–78 | 方向优先排列的 9×7 组合：`N,F,B,D,DF,DB,U,UF,UB` × `无键,LP,MP,HP,LK,MK,HK` |
| 79–80 | 中拳、重拳波动拳 |
| 81 | 重拳升龙拳 |
| 82–84 | 轻脚、中脚、重脚旋风腿 |

旧的轻波动、轻升龙、中升龙分别仍是 12、13、15。
保留重复输入是为旧模型迁移提供稳定编号；迁移仍需扩展输出层并显式声明新接口，
不能仅修改模型标签。

`full_actions.py` 提供 `INTERFACE`、`COUNT`、`FRAMES`、`ACTION_NAMES`、`SPECS`、
`descriptor(action)`、`raw_id(direction, button)` 和 Python 波形参考 `keys`。
`full_actions.lua` 提供 `interface`、`count`、`frames`、`specs`、`descriptor(action)` 和
兼容旧执行器签名的 `keys(action, frame, state, forward)`。Lua `specs` 下标从 1 开始，
描述里的 `id` 从 0 开始。

每个描述包含请求的方向、按钮、强度、`kind` 与 `target`。
普通方向＋按钮的 `target=contextual`：同一个输入可能产生普通攻击或投技，
因此不能只凭请求名称断言“发动了错误招式”。特殊技的目标则分别是
`hadouken`、`shoryuken`、`tatsumaki`；旧前跳重脚宏是 `jump_attack`。

## 执行约束

所有动作始终可选。执行器不根据距离、晕眩、硬直、腾空或对手动作屏蔽、替换、
重试请求，也不插入策略性的等待。前后方向在决策时确定，宏期间不自动转向。
命中、起招、被打断与输入失效是观测问题，不改变这层波形。

新方向＋单键输入在第 0–10 帧保持，最后一帧松开攻击键、保留方向。
这保留当前接口的松键语义，使重复决策能形成新的按键边沿。
纯方向输入保持 12 帧；三个特殊技族采用固定的短方向序列并松键。
这些时长是输入接口的定义，**不是招式的硬直时长**。

这里的“完整”指上述 Ken 招式类别均有对应输入路径，并不等于人类手柄所有
逐帧组合：仍没有任意多键同时按下，也没有模型自由选择每个按键的持续帧数。
模型需要自己学会起跳后何时攻击、何时尝试投技、如何衔接招式。
单元测试证明输入覆盖和波形一致，不代表每一招都已在原生游戏中成功发动。

## 验证

```sh
python -m unittest experiments.rl.test_full_actions -v
```

测试实际运行 Lua，核对 85×2×12 个输出，与独立 Python 波形参考逐项比较；
另用旧动作构建器生成的 Lua 核对前 16 个动作完全相同。
独立覆盖检查包括九方向六按钮、九种特殊技输入、双向投技请求、最后一帧松键，
以及让状态读取直接报错来证明执行器没有偷偷使用对局状态限制动作。

2026-09-12 的 MAME 0.288 原生烟雾测试也已完成：从同一个训练用 Guile 开局分别
请求全部 85 个动作，每例 180 帧，共 15,300 帧，耗时约 31.4 秒。
85×12 帧的请求波形全部匹配，另外逐项对照独立 Python 波形与实际 P1 端口读数，
1,020 次比较无差异。九种特殊技请求均进入了特殊技动画：

| 输入族 | 轻／中／重首次特殊技动画地址 |
| --- | --- |
| 波动拳 | `0x5F2F2` / `0x5F356` / `0x5F3BA` |
| 升龙拳 | `0x5F41E` / `0x5F4CA` / `0x5F576` |
| 旋风腿 | 三档共用起手 `0x5F622`，不能只凭该起手地址区分强度 |

这证明了此开局下的实际输入时序和特殊技启动，不是胜率测试，也没有 PPO 更新。
它没有穷举左右两侧、近／远身、空中、取消窗口或所有投技成功场景；这些上下文的
原生验证与执行反馈识别仍须分别保留证据，不能把 85 个输入选项误称为 85 种招式。
