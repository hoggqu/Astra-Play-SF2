# 并行 PPO 实验：2026-09-11

本轮将首版的 4096 次决策增加到每个种子 102400 次，并引入多个自然开局、
8 个采样 worker、固定开发评估和最终预留检查。模型仍从随机初始化开始，
没有模仿学习，也没有改动冻结 V4。首轮失败结果保留在[试跑记录](RESULTS.md)。

## 环境与数据

- 远端 Ubuntu 24.04.2 / WSL，13900KS，32 个逻辑 CPU，可见约 47 GiB RAM。
  Python 3.12.3、MAME 0.288、SB3 2.7.1、PyTorch 2.14.0 CPU、Gymnasium 1.2.3。
- 静音、无窗口、模拟器不限速；4090 未参与计算。本机 macOS 承担开发和检查，
  两组参数更新均在远端完成，不是两台机器同步更新同一个模型。
- 使用冻结 V4 在一次启动内自然投币，取得 6 个最高难度 7 的 Blanka 满血 R1。
  采集耗时 276.50 秒，期间开始 54 场对手比赛；采集失败和中止也保留在日志中。
- 按采集顺序固定分为 4 个训练开局、1 个 dev 开局、1 个 holdout 开局。
  每个评估开局使用 2/6/10 帧等待条件。不同文件哈希不保证游戏轨迹统计独立。
- PPO 的网络、动作、观察与奖励延续首版。每 worker 收集 256 次决策，
  总 rollout 为 2048；每 10240 次总决策保存模型并评估 dev。
  按 dev 胜率、其次平均回报选模，完成选择并重载后才评估 holdout。

## 吞吐与资源

先在相同训练池上顺序运行随机动作 benchmark，各 4096 次总决策，不做 PPO 更新
或查看 dev/holdout：

| 采样 worker | 采样耗时 | 总决策/秒 | 进程组内存峰值 |
|---|---:|---:|---:|
| 4 | 41.73 秒 | 98.16 | 1.32 GiB |
| 8 | 23.74 秒 | 172.53 | 2.44 GiB |

8 worker 在这个测量中为 4 worker 的 **1.76 倍吞吐**。这不是 GPU 加速结果，
也不能直接与旧 Mac 单开局试跑推算硬件加速比。

随后 seed 42 / 43 两个服务并行，各 8 worker。按用户要求提高资源额度，
每组 CPU 配额 10 个逻辑 CPU、内存上限 12 GiB、禁止交换、Nice 10；
合计配额 20 个逻辑 CPU / 24 GiB，为其他桌面应用保留余量。
systemd 最终记录每组内存峰值约 2.6 GiB，交换使用为 0；两组均正常退出。

## 结果与解释

两组均完成全部预算，没有控制器错误或无效运行。所有下表胜负为小局，
不是对手整场比赛或通关。每列评估只有一个开局的三个等待条件：

| 未训练模型 dev 胜/负/平 | 0/3/0 | 0/3/0 |
| V4 dev 胜/负/平 | 2/1/0 | 2/1/0 |
| 选中模型所在决策数 | 51200 | 71680 |

| 选中模型 holdout 平均回报 | 1.1470 | 1.1429 |
| V4 holdout 平均回报 | 1.2269 | 1.2269 |

程序内部总计时包括环境初始化、评估、保存和关闭，不包含 Python 导入前后的
全部服务启动开销。与训练耗时相差约 228 / 241 秒，约占总计时 24% / 25%；
没有进一步分解计时，不能把差值全部归因于 IPC 或评估。systemd 两组累计 CPU
时间分别为 7534.907 / 7919.311 秒，这是多个核心的累计量，不是墙钟耗时。

两个种子合计采样 **1600 个完整训练小局、204800 次决策**；未完成片段不计输赢。
训练采样使用随机探索且模型不断变化，不能拿其全程胜率与最后确定性评估直接比较。
完整与未完成片段的决策数之和已核对，均等于各自预算。训练小局均为 Blanka、
原生有效难度 7。保存模型哈希已复核。

真实胜率 100% 的估计。训练中的中间评估仍有波动。
