# TIME 授分与 KO 标记同帧变化：v5 候选

一次 128×128 训练在 113,664 决策处 invalid。原始完整未决记录明确显示：
对手 Dhalsim，frame 3044 timer 归零，Ken live/display 为 1，CPU 为 42；
3073 仍保持该血量及 0:0 比分。3074 同一原生帧把 CPU pip 加一，锁存
TIME HP 为 1/42，同时把 Ken 的 live HP 改为 `-1`，display 仍为 1。
旧 v4 要求授分时双方 live HP 与锁存同时相等，因此没有记录该次原生授分。
这是漏识别一局已确定的 TIME 失利，不是未知平局或模型错误。

`settlement_v5.lua` 保留旧路径，增加一个严格的相邻帧路径：

- 当前 timer=0、唯一合法的 +1 pip、合法整数锁存 HP、显示与锁存一致、
  获胜侧 HP 排序正确。
- 紧邻前一原生 tick 的原始快照仍为 timer=0、同角色、旧比分；双方
  live=display，且它们恰好等于当前锁存 HP。
- 当前失败侧 live 必须为原生 KO 标记 `-1`，胜方 live 保持锁存值。
- 授分后原比分、锁存和显示仍必须稳定至少 360 原生帧，并满足旧局成熟、
  双方落地条件；任何异常仍 invalid，不重置证据、不复活 invalid Core。

不增加角色/动画白名单，不读未来状态，不修改 RAM。前后原始快照各自
保存在 `time_award.previous/state`；成熟 `settled` 仍是旧局原始快照，
奖励计算及下一局补血隔离不改。新的识别标签是
`rl-native-time-pip-adjacent-ko-v5`。旧同帧 live 路径仍使用 v2 标签。
上层原有 native tick 去重/缺帧检查是此协议的必需前提。

离线检查使用完整 866 帧原始轨迹：旧 v4 重现 invalid；v5 在 3434 帧
记录 loss 0:1，距离授分恰好 360 帧，早于下一局 3909 帧。反例覆盖比分
双增/跳变、缺少或非相邻前帧、旧分数不符、锁存/显示不符、错误 KO 标记、
授分后数据变化、空中、提前下一局以及 invalid 不复活。

一次独立训练专用原生重放使用同一训练存档、lead12、原 254 个宏动作，
只有初始 load，场内不暂停。3044..3434 共 391 个状态与原失败轨迹逐字段
一致；3434 记录成熟失利，3998 正常进入 R2 并执行首个完整 12 帧宏。
探针在 4050 帧主动结束，明确为 partial，不算完整比赛或正式通关。
另一次启动前源目录布局检查失败尚未启动 MAME，记录单独保留。

可复用工具：`settlement_v5_replay`（离线原始轨迹）、
`settlement_v5_probe`（有界初始 load 的原生诊断）及
`test_settlement_v5`。原 invalid 永不回填为 valid。

v5 目前仅用于新复制的冻结包；现有 v4 活动包不更换。恢复训练应从
102,400 决策的完整 checkpoint 继承，保留 4,400 次优化器更新；其后的
11,264 个没有完整保存的决策不计入恢复模型。新 307,200 决策使用新 seed
并重启环境 RNG，必须明确它不是原 409,600 决策完整配对 A/B 试验。
