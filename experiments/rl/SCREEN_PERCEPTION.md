# 结构化画面感知实验

本实验建立新的 `sf2_screen_perception_v2` 观测身份，保留 full85 v1 源包和旧模型。它根据当前已锁存的精灵绘制列表及此前观察到的变化构建结构化信息，并非把整幅截图或每个背景像素输入模型。无法可靠辨认的状态、动作或飞行道具归属必须保留未知，不借用隐藏计时器或未来动作阶段来补齐。

动作接口仍是 `ken_actions85_full_v1`，每次决策执行 12 个原生帧。奖励、折扣、GAE、成熟判胜、投币导航及动作集合不变；没有动作遮罩、禁止重复输入或额外脚本战斗策略。网络仍为共享标准 MLP，旧观测模型不能直接加载。

需要更宽的共享网络时，使用独立的 [128×128 候选](PERCEPTION128.md)；本页的 64×64 版本与既有验证记录保持冻结。

## 输入清单

每次决策取当前 **1,129 项**结构化观测，与此前三次决策观测组成 **4,516 项**输入。原生观察器则逐帧运行，能够记录两次决策之间实际看到过的短暂动作。

| 部分 | 每次观测字段 | 来源与限制 |
|---|---|---|
| 基础状态 | 双方显示血量、计时、渲染包围框位置、水平相对距离、落地状态、对手身份，共 22 项 | 输入使用 `displayed_hp`，不使用即时内部血量；位置取匹配到的当前精灵图块包围框中心 X / 底部 Y，以屏幕 384×224 坐标表示。无法匹配时位置为未知，不回退到当前内部物理坐标。原有 64 项内部动作状态 one-hot 删除。 |
| 先前请求的执行反馈 | 请求动作、观察到的结果/实际动作种类/可识别强度、已观察的经过时间、双方可见眩晕，共 114 项 | 新身份 `ken_screen_execution_feedback_v2`。只消费可见角色观察器的已解析证据，不再读取 `a` 或动画指针来推断动作已经发动。 |
| 双方角色 | 当前姿态、可辨动作/变体、状态、朝向、已得小局数、位移、已观察的姿态/状态经过时间，以及最近看到的攻击，共 872 项 | 相同当前形象不能仅因内部动画路径不同而得到不同标签；无法区分的字段为未知。经过时间是过去观察所得，不是剩余恢复/受击硬直或未来动画时长。 |
| 可见飞行道具 | 至多 8 个对象槽的存在、绝对屏幕位置、已观察位移、可辨归属及种类，共 121 项 | 包括静止火焰。只跟踪已出现对象；不预测尚未出现的道具，不使用隐藏归属指针、目标血量或未来速度。位置取当前图块群中心，以 384×224 屏幕坐标表示，角色暂不可辨时仍保留道具位置。 |

双方眩晕是可见的晕眩姿态，不是内部累计眩晕值。位置与显示几何用于表达角色、可见道具之间的关系；静态背景装饰不作为额外输入。具体识别范围、未知情况及版本验证记录见[角色感知](FIGHTER_PERCEPTION.md)与[飞行道具感知](VISIBLE_PROJECTILES.md)。画面姿态可以被识别并保留独立身份，但其动作名称仍可能因视觉歧义而未知；接口存在不等于所有动作都已可靠命名。

当前地面接触没有可靠的画面证明时编码为未知 `-1`；胜局图标没有独立显示解码器时也保留未知，不能用内部字段补齐。显示血量与计时采用原 HUD 数据字段，尚不声明它们与每一个截图像素在同一时刻完全一致。

当前实现按屏幕边界裁剪精灵图块，但未完整计算图块透明像素、人物互相遮挡及其他图层的逐像素遮盖。被覆盖的绘制条目仍可能参与识别，因此应称为**结构化渲染感知**，不能宣称等同于只看最终截图的视觉模型。它已去掉内部动作字节、未来意图与提前的物理坐标输入；逐像素遮挡是明确保留的限制。

显示血量读取为 `-1` 时按已耗尽的空血条编码为 0；其他超出 `[-1,144]` 的数值、缺失或非有限值编码为明确未知 `-1`。这是显示字段的边界处理，不把内部即时血量送入观测；训练奖励仍沿用原内部伤害计算。

## 时间顺序

每个推进的原生帧依次读取当前可见字段、更新角色观察器、更新道具观察器、更新先前请求的执行反馈，再进入原有 Core 与决策。新请求在读取当前观测、选择动作以后才登记，不修改已保存的观测。自然新小局、训练读档和新场次都重置观察器与四份历史。

batch 训练和不中断的 native continuous 使用同一组观察器与顺序。原生帧记录及决策记录分别保留角色、道具与执行反馈快照，供离线重建观测；原有时钟、禁止局中暂停、模型/源哈希和成熟比分审计继续执行。

## 便携构建

安装主项目和 RL 可选依赖后，构建命令只读取公共源码，不需要作者的私有目录、ROM、存档或旧模型：

```sh
python -m experiments.rl.perception_builder --output .local/rl-code/perception-001
python .local/rl-code/perception-001/launch.py initialize \
  --output .local/rl-runs/perception-initial-001 --seed 852
```

也可通过 `--source` 指定已冻结的 full85 v1 源包根目录。所有输出均使用新目录，保留完整父级源码、构建配方和哈希。生成后可移动目录，运行时不需要原构建路径。

实际训练仍需已配置的 MAME 0.288 / World 910522，以及通过校验的数据集。与 full85 相同，通用集合每名声明对手需要 8 个唯一 train 开局及独立 dev/holdout；只有 train 送入环境。

```sh
python .local/rl-code/perception-001/launch.py batch_train \
  --dataset .local/rl-data/full85-openings-001/manifest.json \
  --init-model .local/rl-runs/perception-initial-001/ppo-initial.zip \
  --workers 1 --steps 256 --seed 852 --output .local/rl-runs/perception-smoke-001
python .local/rl-code/perception-001/launch.py export \
  --model .local/rl-runs/perception-smoke-001/ppo-batch.zip \
  --output .local/rl-runs/perception-export-001
python .local/rl-code/perception-001/launch.py native_continuous \
  --model .local/rl-runs/perception-smoke-001/ppo-batch.zip \
  --difficulty 3 --attempts 1 --speed fast --output .local/rl-runs/perception-play-001
```

短训练仅用于验证模型、观测、优化器与导出接通。原生门禁、实际 PPO 更新和自然投币结果分别记录；没有经过验证的结果不会写成通关率，也不继承旧冻结版本的 10/20 成绩。

## 已完成的功能验证

World 910522 / MAME 0.288 上的新接口完成以下检查：

- 415 项离线测试通过，包含公共源码构建、生成包搬迁、旧模型拒绝、Lua/Python 特征与 Lua/Torch 推理一致性，以及内部血量/动作/物理字段改变不影响既有画面观测的反例。
- 85 个动作的原生门禁通过：三条 batch、显式 reset 与连续运行路径各 1,332 帧，逐帧状态、4,516 项观测、反馈和实际输入端口完全一致。
- 11 名对手的独立开局检查共 1,584 帧、132 次观测，双方姿态及位置在这一有限样本内均可辨认。语义状态可辨比例分别为 1,027/1,584 与 969/1,584；其余保留姿态身份和未知语义，未借用内部动作信息补全。
- 一次 256 决策的真实 PPO 短训练完成参数及 Adam 更新、保存和导出，耗时约 23.4 秒。
- 使用该短训练模型自然投币一次，正常难度对 Blanka 以 0:2 失败：3,274 个原生帧、192 次决策、局中暂停 0 次，原生与接口审计均通过。独立 Torch 重建核对全部 192 次 Lua 决策一致。

这些结果证明新观测能贯通采集、训练、导出与连续游玩。256 步模型的单次失败只是功能验证记录，不是策略强度评估，也没有产生新的通关率认证。
